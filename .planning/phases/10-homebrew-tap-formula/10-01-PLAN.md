  <action>
1. Create the GitHub repo:
   ```bash
   gh repo create darrelldoesdevops/homebrew-tap --public --description "Homebrew tap"
   ```

2. Clone the repo to a temporary working directory:
   ```bash
   cd /tmp && gh repo clone darrelldoesdevops/homebrew-tap && cd homebrew-tap
   mkdir Formula
   ```

3. Fetch REAL SHA256 values from the v1.1.0 release sidecar files:
   ```bash
   ARM_SHA=$(curl -sL https://github.com/darrelldoesdevops/contentops/releases/download/v1.1.0/contentops-aarch64-apple-darwin.sha256 | awk '{print $1}')
   INTEL_SHA=$(curl -sL https://github.com/darrelldoesdevops/contentops/releases/download/v1.1.0/contentops-x86_64-apple-darwin.sha256 | awk '{print $1}')
   ```
   Verify both are 64-character hex strings. Abort if either is empty.

4. Write `Formula/contentops.rb` using the production-ready template from 10-RESEARCH.md with these specifics:
   - `version "1.1.0"` (matches v1.1.0 release tag, no `v` prefix)
   - ARM url: `https://github.com/darrelldoesdevops/contentops/releases/download/v1.1.0/contentops-aarch64-apple-darwin`
   - Intel url: `https://github.com/darrelldoesdevops/contentops/releases/download/v1.1.0/contentops-x86_64-apple-darwin`
   - ARM sha256: the real value from step 3
   - Intel sha256: the real value from step 3
   - `license "MIT"`
   - `depends_on :macos` and `depends_on "ffmpeg"`
   - **Top-level architecture selection (DSL blocks):** `on_macos do` / `on_arm do` / `on_intel do` wrapping `url` and `sha256` declarations. These are DSL-level constructs evaluated at parse time — required because `Hardware::CPU.arm?` cannot be used at the formula body level (it would raise a parse error).
   - **Install-time binary selection (`def install`):** Use `Hardware::CPU.arm?` / `Hardware::CPU.intel?` conditionals inside `def install` to pick the correct downloaded filename for `bin.install "contentops-<arch>-apple-darwin" => "contentops"`. This is required because `on_arm do` blocks do NOT work inside method bodies — `Hardware::CPU` is the correct runtime check there.
   - NOTE: Both patterns are intentionally used together. They are NOT conflicting — they serve different scopes (DSL declarations vs runtime method body). See 10-RESEARCH.md "Anti-Patterns" and "Production-Ready Template" sections for the authoritative pattern.
   - `def caveats` with moderate verbosity per user decisions: whisper-cli with URL, model mention (no specific model), Claude CLI as optional with URL, FFmpeg auto-installed note, `contentops doctor` hint
   - `test do` block with `assert_match version.to_s, shell_output("#{bin}/contentops --version")`
   - Inline sentinel comments on all 5 auto-update values: `# === AUTO-UPDATE: VERSION ===`, `# === AUTO-UPDATE: ARM-URL ===`, `# === AUTO-UPDATE: ARM-SHA256 ===`, `# === AUTO-UPDATE: INTEL-URL ===`, `# === AUTO-UPDATE: INTEL-SHA256 ===`
   - 2-3 line header comment explaining the sentinel system for future maintainers

5. Commit and push:
   ```bash
   cd /tmp/homebrew-tap
   git add Formula/contentops.rb
   git commit -m "feat: add contentops formula for v1.1.0"
   git push
   ```

6. Verify the formula syntax is valid Ruby:

   ruby -c Formula/contentops.rb
