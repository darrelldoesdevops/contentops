  <files>src/cli.rs, src/commands/caption.rs</files>
  <action>
In `src/cli.rs`:
- Add `burn: bool` field to `CaptionArgs` with `#[arg(long)]` attribute and doc comment "Burn captions into video"

In `src/commands/caption.rs`:
- Add a `generate_ass` function that takes `&[Word]` and returns a `String` containing a valid ASS subtitle file. Implementation details:

  **ASS Header (Script Info section):**
  - `ScriptType: v4.00+`
  - `PlayResX: 1080`, `PlayResY: 1920` (TikTok portrait)
  - `WrapStyle: 0` (smart wrapping)

  **ASS Style (V4+ Styles section):**
  - Style name: `Default`
  - Font: `Arial`, size `48`, bold (`-1`)
  - PrimaryColour: `&H00FFFFFF` (white -- the unhighlighted/pre-karaoke state color)
  - SecondaryColour: `&H0000FFFF` (yellow -- the karaoke fill color, what words highlight TO)
  - OutlineColour: `&H00000000` (black outline)
  - BackColour: `&H00000000` (black shadow)
  - BorderStyle: `3`, Outline: `2`, Shadow: `0`
  - Alignment: `2` (bottom-center)
  - MarginL: `40`, MarginR: `40`, MarginV: `320` (avoids bottom 320px TikTok safe zone)

  **ASS Events (Events section):**
  - Reuse the same word grouping logic as SRT (3-5 words per entry, break on punctuation). Call existing `group_words_into_srt` to get the word groups, but you also need per-word timing. So create a new function `group_words_for_ass` that returns groups where each group contains the individual `Word` items (not just concatenated text). Each group becomes one ASS Dialogue event.
  - For each Dialogue event line:
    - Format: `Dialogue: 0,{start},{end},Default,,0,0,0,,{text_with_k_tags}`
    - Timestamps use ASS format: `H:MM:SS.cc` (centiseconds, NOT milliseconds)
    - Within each event, build the text with `\kf` tags: for each word in the group, emit `{\kf{duration}}{word} ` where `duration` is `(word.end - word.start) * 100` rounded to integer (centiseconds). The `\kf` tag makes each word smoothly fill with the SecondaryColour over its duration.

  **ASS timestamp helper:**
  - Add `format_ass_time(seconds: f64) -> String` that formats as `H:MM:SS.cc` (e.g., `0:01:23.45`). This is different from SRT format.

  Verify: `cargo build` succeeds. The `--burn` flag is accepted by the CLI parser but does not yet produce output (pipeline integration is Task 2).

<task type="auto">
  <name>Task 2: FFmpeg burn pipeline and caption command integration</name>
  <files>src/commands/caption.rs</files>
  <action>
In `src/commands/caption.rs`, extend the `run` function to handle the `--burn` flag:

After the existing SRT + JSON generation block (step 6-7), add the burn pipeline when `args.burn` is true:

1. **Derive output path:** Use `derive_caption_output(&args.input, "captioned", "mp4")` for the burned video output path.

2. **Generate ASS temp file:**
   - Call `generate_ass(&words)` to get the ASS content string
   - Create a temp file using `make_temp_file(parent_dir, ".ass")`
   - Register it with the registry
   - Write the ASS content to the temp file using `std::fs::write`

3. **Run FFmpeg burn:**
   - Build the video filter string: `format!("ass={}", ass_path.to_string_lossy())` where `ass_path` is the temp ASS file path
   - FFmpeg args: `["-i", input, "-vf", &vf_string, "-c:v", "libx264", "-crf", "23", "-preset", "medium", "-pix_fmt", "yuv420p", "-c:a", "copy", output]`
   - Show spinner: "Burning captions..." (reuse existing `make_spinner` pattern)
   - Call `ffmpeg::run_ffmpeg` or `ffmpeg::run_ffmpeg_verbose` based on `verbose` flag
   - Handle success/failure matching the existing audio extraction error pattern (FfmpegFailed with stage "caption-burn")

4. **Cleanup:** Remove the temp ASS file after burn completes (success or failure). Remove from registry.

5. **Success output:** Print the video output path and file size using the same `format_size` pattern as existing SRT/JSON output messages.

Important: The burn pipeline runs AFTER SRT + JSON generation. Both SRT + JSON AND the burned video are produced when `--burn` is passed. When `--burn` is NOT passed, behavior is unchanged (SRT + JSON only).
