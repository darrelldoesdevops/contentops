Two changes in two repos:

**1. contentops repo — append `update-tap` job to `.github/workflows/release.yml`**

Add a new job after the existing `release` job:

```yaml
  update-tap:
    name: Update Homebrew Tap
    needs: release
    runs-on: ubuntu-latest
    steps:
      - name: Trigger tap update
        run: |
          gh workflow run update-tap.yml \
            -f version="${GITHUB_REF_NAME#v}" \
            -R darrelldoesdevops/homebrew-tap
        env:
          GH_TOKEN: ${{ secrets.TAP_UPDATE_TOKEN }}
```

Key details:
- `needs: release` ensures assets are uploaded before dispatch
- `${GITHUB_REF_NAME#v}` strips the `v` prefix (e.g. `v1.2.0` -> `1.2.0`) because the formula stores version without `v`
- `GH_TOKEN` uses `TAP_UPDATE_TOKEN` (NOT `GITHUB_TOKEN` -- `GITHUB_TOKEN` cannot trigger cross-repo workflows)
- Runs on `ubuntu-latest` (no macOS needed -- just a gh CLI call)

**2. darrelldoesdevops/homebrew-tap repo — create `.github/workflows/update-tap.yml`**

Clone the homebrew-tap repo, create the workflow file, commit and push.

The workflow accepts a `version` input via `workflow_dispatch`, fetches SHA256 from `asset.digest` via GitHub API, patches all 5 sentinel-marked fields with sed, and commits+pushes.

Full workflow content:

```yaml
name: Update Formula

on:
  workflow_dispatch:
    inputs:
      version:
        description: 'Version (without v prefix, e.g. 1.2.0)'
        required: true
        type: string

jobs:
  update-formula:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4

      - name: Fetch SHA256 from release
        id: sha256
        run: |
          ARM_SHA=$(gh api repos/darrelldoesdevops/contentops/releases/tags/v${{ inputs.version }} \
            --jq '.assets[] | select(.name == "contentops-aarch64-apple-darwin") | .digest | ltrimstr("sha256:")')
          INTEL_SHA=$(gh api repos/darrelldoesdevops/contentops/releases/tags/v${{ inputs.version }} \
            --jq '.assets[] | select(.name == "contentops-x86_64-apple-darwin") | .digest | ltrimstr("sha256:")')
          echo "arm_sha=$ARM_SHA" >> "$GITHUB_OUTPUT"
          echo "intel_sha=$INTEL_SHA" >> "$GITHUB_OUTPUT"
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}

      - name: Patch formula
        run: |
          VERSION="${{ inputs.version }}"
          ARM_SHA="${{ steps.sha256.outputs.arm_sha }}"
          INTEL_SHA="${{ steps.sha256.outputs.intel_sha }}"
          F="Formula/contentops.rb"

          sed -i "s|\(# current version: \)[^ ]* \(=== AUTO-UPDATE: VERSION ===\)|\1${VERSION} \2|" "$F"
          sed -i "s|\(url \"https://github\.com/darrelldoesdevops/contentops/releases/download/v\)[^/]*\(/contentops-aarch64-apple-darwin\" # === AUTO-UPDATE: ARM-URL ===\)|\1${VERSION}\2|" "$F"
          sed -i "s|\(sha256 \"\)[^\"]*\(\" # === AUTO-UPDATE: ARM-SHA256 ===\)|\1${ARM_SHA}\2|" "$F"
          sed -i "s|\(url \"https://github\.com/darrelldoesdevops/contentops/releases/download/v\)[^/]*\(/contentops-x86_64-apple-darwin\" # === AUTO-UPDATE: INTEL-URL ===\)|\1${VERSION}\2|" "$F"
          sed -i "s|\(sha256 \"\)[^\"]*\(\" # === AUTO-UPDATE: INTEL-SHA256 ===\)|\1${INTEL_SHA}\2|" "$F"

      - name: Verify patches
        run: |
          VERSION="${{ inputs.version }}"
          if grep "AUTO-UPDATE" Formula/contentops.rb | grep -qv "${VERSION}"; then
            echo "ERROR: Not all sentinels were patched"
            grep "AUTO-UPDATE" Formula/contentops.rb
            exit 1
          fi

      - name: Commit and push
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git add Formula/contentops.rb
          git diff --cached --quiet && echo "No changes to commit" && exit 0
          git commit -m "chore: update contentops formula to v${{ inputs.version }}"
          git push
```

Key details:
- `GITHUB_TOKEN` in the tap workflow has `contents: write` via `permissions:` -- sufficient to push to homebrew-tap main branch
- `GH_TOKEN` in SHA256 fetch uses `GITHUB_TOKEN` because contentops is a public repo -- no cross-repo PAT needed for reading
- The tap workflow does NOT need `TAP_UPDATE_TOKEN` -- only contentops release.yml needs it
- Verify step catches incomplete patches before committing
- `git diff --cached --quiet` exits cleanly if no changes (idempotent)
- GNU sed on ubuntu-latest uses `sed -i` without `''`

Use `gh` CLI to clone homebrew-tap, create the workflows directory, write the file, commit, and push.
