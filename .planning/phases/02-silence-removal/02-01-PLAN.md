<feature>
  <name>Silence detection parsing, padding, and filter expression building</name>
  <files>src/silence.rs, tests/silence_tests.rs</files>
  <behavior>
    **Struct: SilenceInterval** — represents a detected silent segment with `start: f64` and `end: f64` (seconds).

    **Struct: SpeechInterval** — represents a kept speech segment with `start: f64` and `end: f64` (seconds).

    **Function: parse_silencedetect(stderr: &str, duration: f64) -> Vec&lt;SilenceInterval&gt;**

    Parses FFmpeg silencedetect stderr output. FFmpeg emits lines like:
    ```
    [silencedetect @ 0x...] silence_start: 1.504
    [silencedetect @ 0x...] silence_end: 3.200 | silence_duration: 1.696
    ```

    Cases:
    - Normal: pairs of silence_start/silence_end → SilenceInterval { start, end }
    - Trailing silence: silence_start with no following silence_end → use `duration` param as end
    - Leading silence: silence_end appears before any silence_start → insert SilenceInterval { start: 0.0, end }
    - No silence detected: empty stderr or no matches → empty Vec
    - Multiple segments: parse all pairs in order

    Test cases:
    - `parse_silencedetect("", 60.0)` → `[]`
    - `parse_silencedetect("[silencedetect @ 0x1] silence_start: 5.0\n[silencedetect @ 0x1] silence_end: 8.0 | silence_duration: 3.0\n", 60.0)` → `[SilenceInterval { start: 5.0, end: 8.0 }]`
    - Trailing: stderr has `silence_start: 55.0` with no end, duration=60.0 → `[..., SilenceInterval { start: 55.0, end: 60.0 }]`
    - Leading: stderr starts with `silence_end: 2.0` → `[SilenceInterval { start: 0.0, end: 2.0 }, ...]`
    - Mixed FFmpeg output: other FFmpeg log lines interspersed → only silencedetect lines parsed

    **Function: silence_to_speech(silences: &[SilenceInterval], duration: f64, padding: f64) -> Vec&lt;SpeechInterval&gt;**

    Inverts silence intervals to speech intervals, then applies padding (expand speech into adjacent silence by `padding` seconds on each side).

    Cases:
    - No silence → single SpeechInterval { start: 0.0, end: duration }
    - Silence at 5.0-8.0 in 60s video, padding 0.2 → speech [0.0, 5.2] and [7.8, 60.0]
    - Adjacent speech segments after padding that would overlap → clamp (no overlap, no negative starts)
    - Padding exceeding silence gap → segments merge or clamp to not overlap
    - Silence covers entire video → empty Vec (no speech)

    **Function: build_select_filter(speeches: &[SpeechInterval], frame_rate: f64) -> String**

    Builds the FFmpeg `-vf` select filter string:
    `select='between(t,0.000,5.200)+between(t,7.800,60.000)',setpts=N/{frame_rate}/TB`

    Cases:
    - Single speech segment → `select='between(t,S,E)',setpts=N/{frame_rate}/TB`
    - Multiple segments → `+` separated between() expressions
    - Empty speeches → empty string (caller handles)

    **Function: build_aselect_filter(speeches: &[SpeechInterval]) -> String**

    Same as select but for audio:
    `aselect='between(t,0.000,5.200)+between(t,7.800,60.000)',asetpts=N/SR/TB`

    **Function: total_silence_removed(silences: &[SilenceInterval], padding: f64) -> f64**

    Returns total seconds of silence that will be removed (accounting for padding eaten from each side). Used for the success message.
  </behavior>

    Timestamps formatted to 3 decimal places in filter expressions.

    The module is pure logic with no FFmpeg subprocess calls -- those are in Plan 02.
